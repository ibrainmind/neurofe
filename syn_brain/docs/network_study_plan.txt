NETWORK-SCALE STUDY PLAN: FROM ONE JR NODE TO A 10-20 NODE NETWORK
===========================================================================

Status     : proposed, 2026-11-24
Builds on  : the single-node study (E1-E12, bifurcation_followup.pdf,
             single_node_conclusions.pdf, ei_balance_bifurcation_map.pdf,
             jr_parameters_explainer.pdf) and the Phase 1 network gate
             (syn_brain/README.md, "Phase 1 results"), which failed.
Executive summary : syn_brain/reports/executive_summary.pdf, section 5,
             step 3 ("Fisher spectrum of the 10-node network (S1, S2)")


1. WHY THIS PLAN
----------------

Phase 1 already tried a 10-node network (tier S1, neurofe's real JansenRit.fit)
and failed: only k was recovered; mu got no gradient at all (delays are cast
to integers); g, c1, c2 stayed at their starting values (gradients ~1e-6,
~1e4x smaller than a or k); b, c4, std_in converged to the SAME value
regardless of the teacher's truth (they absorb mismatch, carry no
information). That failure was diagnosed, not explained away, by the
single-node study that followed it:

  * neurofe's raw parameterisation (Adam, lr 0.05) is a large, avoidable part
    of the failure on its own: log-scaled parameters reach ~250x lower loss
    on identical single-node data (single_node_tms_study.pdf).
  * c1, c2, c3, c4 are not identifiable INDIVIDUALLY in this model class, by
    construction (section 2, single_node_study_plan.txt) -- no amount of
    network-level data changes that; only the products c1*c2, c3*c4 can ever
    be recovered, and only when the node is in an engaged (firing) state.
  * neurofe's long-range coupling is a zero-mean Laplacian
    (g*sum w_ij*(E_j(t-d_ij) - E_i)); with no mean input anywhere, every node
    rests in the inactive, near-linear state where the E-I loop is invisible
    (docs/background_drive_note.txt). This is likely why b, c4 (which only
    carry information when the loop is engaged) collapsed to arbitrary values
    in Phase 1: the loop was never engaged for any node, in any condition.
  * Pushing a single node into the firing state recovers c3*c4 and, more
    inconsistently, c1*c2 -- but only with a richer stimulus (paired-pulse,
    train, E+I injection), an ensemble of restarts selected by lowest loss,
    and ideally a Laplace posterior rather than a point estimate
    (single_node_conclusions.pdf sections 5-6, validated on 24 teachers).
  * mu's delay cast is not a Phase-1-only accident: it is in neurofe's real
    forward pass (neurofe/models/jansen_rit.py) and is mirrored exactly in
    syn_brain/core/simulator.py (the exact-equivalence teacher). It is,
    however, ALREADY FIXED in a parallel, not-yet-used simulator,
    syn_brain/core/diffsim.py, via fractional delays (linear interpolation
    of the history buffer) -- built, but never wired into a training run.

In short: Phase 1's failure is now understood to be mostly a METHOD failure
(raw parameterisation, no mean drive, non-differentiable mu, single-pulse
stimulus, single point estimate), not evidence that network-scale JR
parameters are inherently unrecoverable. This plan re-attempts the network
with every one of those fixes in place, in small, gated steps, rather than
re-running the same failed recipe at a larger scale.

3. PART N0: BUILD THE HARNESS (no network results yet)
-------------------------------------------------------

Aim
  Make it possible to fit a network with every single-node lesson applied,
  before spending any compute on a network-scale measurement.

Tasks (revised after finding core/fitting.py, scripts/identifiability.py and
scripts/recover_clean.py already built -- see section 2)
  N0.1  DONE this session: added a non-diffusive coupling path to
        core/diffsim.py (coupling_mode="non_diffusive" alongside the
        existing default "laplacian"), of the form
        g * sum_j w_ij * S(E_j(t - d_ij)): neighbours send firing rates,
        which are positive, so a node's mean drive grows with g and its
        in-degree. core/simulator.py (the exact-equivalence teacher) is
        untouched and stays exact.
  N0.2  DONE this session. 3-node tonic-drive-only scan (no stimulation):
        g=0 -> resting E-I = -1.861 mV (matches the single-node rest
        baseline exactly); g=200 -> +5.978 to +5.996 mV (at/above v0=6 mV,
        engaged). 10-node scan: nominal g=1000.01 -> E-I=6.023 mV (fully
        engaged) with ZERO oscillation amplitude at every tested g
        (180-400) over a 9 s window -- no hysteresis/oscillation risk from
        the coupling fix itself at this network size, for this teacher.
        Gate PASSED.
  N0.3  DONE this session, with one correction found and fixed along the
        way. coupling_mode is now threaded through both
        scripts/identifiability.py and scripts/recover_clean.py (plus a
        --g-override flag on both, see below). The correction: nominal
        g=1000.01 -- calibrated for the self-cancelling Laplacian -- makes
        g*coupling reach 2000-5000 under non_diffusive coupling, which
        SATURATES the U_BOUND=500 safety clip in core/diffsim.py's
        step_ms (tanh(rE/U_BOUND)*U_BOUND) and silently kills gradients.
        This is exactly the kind of harness bug N0.3 existed to catch
        before it was mistaken for a network-level finding (see risk list,
        section 8). Fixed by exposing --g-override and sweeping it (N1,
        below) to find an operating point that engages the network without
        saturating.
        STILL OPEN: the >=15-20 restart ensemble wrapper (nominal-centered,
        lowest-loss) is not yet built; N2 below used ONE start per teacher
        as a first pilot, same limitation the single-node study had before
        E9-E12 added the ensemble. Build this next if N2's single-start
        pilot looks promising but noisy.
  N0.4  Multi-condition stimulation per site: identifiability.py and
        recover_clean.py already support multiple SITES and AMPLITUDES
        (the easy two-thirds of "RICH"). Paired-pulse and train still need
        either several diffsim.Protocol calls summed into one loss, or an
        extension of Protocol to multiple pulse epochs per condition --
        scope this only if N1/N2 below show multi-amplitude alone is not
        enough (it was NOT enough at the single-node level either).

Gate to leave N0
  The new coupling engages the loop in the tiny sanity check (N0.2) without
  uncontrolled oscillation; identifiability.py and recover_clean.py run
  end-to-end with coupling_mode="non_diffusive" and produce sensible
  (non-NaN, non-exploding) output, as a check that the harness itself
  introduces no new bugs before trusting it for the Part N1/N2 measurements.


4. PART N1: FISHER/CRB SPECTRUM, 10 NODES, TIER S1 (measure, don't guess)
---------------------------------------------------------------------------

Aim
  Exactly executive_summary.pdf's step 3: before spending any training
  compute, measure which parameter combinations are even in principle
  identifiable in a 10-node network, the cheap way (Jacobians only, no
  optimisation) -- matching how every single-node identifiability claim in
  this study was first checked with Fisher/CRB before backprop.

Design
  Reuse scripts/identifiability.py as-is (already builds a 10-node
  sub-network, tier S1 -- global a,b,g,c1-c4,k,mu -- and a bank of
  multi-site/multi-amplitude protocols, 1-8 sites), adding only the
  coupling_mode="non_diffusive" flag from N0.3. Compute CRB for every
  global parameter and, in post-processing, for the identifiable
  combinations (c1*c2, c3*c4) exactly as in analyse() for the single node.

Measurements
  1. Does mu now get a non-degenerate Fisher entry (nonzero, well-conditioned
     row/column), confirming the fractional-delay fix actually matters, not
     just compiles?
  2. Do the single-node-identifiable combinations (k, a, conditionally
     c3*c4) survive embedding in a network, or does shared input across
     nodes add new degeneracies (e.g. a node's own c1*c2 confounded with its
     neighbours' via g)?
  3. Run once with the new coupling OFF (Laplacian only) and ON
     (non-diffusive), same network and sites, to directly measure how much
     the coupling fix matters -- the network analogue of the single-node
     tonic-drive sweep.
  4. Repeat at tier S2 (release w_bb) to measure how much adding per-edge
     connectivity degrades single-node-level identifiability, before ever
     training S2.

Gate to leave N1
  At least k, a, and one loop-gain combination (c3*c4) show a CRB bound
  under 20% at tier S1 with the coupling fix on, for at least one
  stimulation design. If NOTHING survives even in the Fisher/CRB best case,
  stop here and report it as a finding (no point training), rather than
  spending backprop compute on a result already ruled out analytically --
  this mirrors how Part A of the single-node study plan used Fisher sweeps
  as a gate before any training.

RESULTS (measured this session, nominal teacher, 10 nodes, tier S1, "8
sites, 3 amplitudes" -- the richest built-in protocol)

  CRB relative SE, %, by coupling mode / g:

         (g=1000)   g=1000

  g      0.0033     130        5.3    3.1    2.3    1.6    0.68   1.6   2.4
  c1     2.5        1100       15     7.8    4.7    1.8    1.1    5     5.5

  c3     1.1        1.7        2      2.5    2.5    1.3    0.56   4.2   10

  Gate PASSED, comfortably, for BOTH coupling modes at their respective
  best operating points -- a different and more positive situation than
  the single-node study ever found.

  Three findings, in order of how much they revise this plan's premise:

  1. non_diffusive g=1000.01 (the teacher's own nominal value) is
     CATASTROPHIC, not just suboptimal: g, c1, c2, mu all blow out to
     35-1400% relative SE. Root cause confirmed by direct computation, not
     inferred: per-node g*coupling reaches 2000-5000 at this g, against
     U_BOUND=500 -- the tanh clip saturates and the gradient through that
     pathway is ~zero. This is the N0.3 bug described above, not a
     property of the non-diffusive idea itself.
  2. Once g is brought into a non-saturating range, non_diffusive has a
     clear interior sweet spot at g~=100-120: every parameter is under ~2%
     (mu=0.93%, the long-standing Phase-1 blind spot, and g itself=0.68%,
     both excellent). Degradation runs in OPPOSITE directions on either
     side -- g>=150 re-approaches saturation (g, c1, c2, mu degrade); g<=70
     under-engages the network (c3, c4 degrade sharply instead: c4 goes
     1.7%->22% from g=100 to g=50). This mirrors the single-node
     quiet/saturated bifurcation story, but for the coupling's own gain,
     not stimulus amplitude.
  3. UNEXPECTED, and the one that most changes this plan's framing: the
     existing Laplacian (rest, zero mean drive -- what Phase 1 actually
     used) is ALREADY excellent at network scale for every parameter
     (worst case c4=2.7%), including mu (0.003%) and g (0.0033%) -- better
     than non_diffusive's own best g=100 row for a,b,g,c2,mu,k, and only
     somewhat behind it for c1,c3,c4. This is NOT the single-node story,
     where rest-state c1-c4 bounds were 56-250% with one pulse. The
     likely reason: "8 sites, 3 amplitudes" is 24 largely-independent
     conditions, each probing the SAME global parameters from a different
     anatomical angle (site location, conduction delay) -- pooling many
     diverse conditions can constrain a shared global parameter even
     without any single node individually in a special operating regime.
     This does NOT mean Phase 1 should have succeeded at rest: Phase 1
     failed with this exact Laplacian coupling, using neurofe's real
     JansenRit.fit. The gap between "CRB says rest is fine" and "Phase 1's
     real backprop got stuck at rest" is now the single most important
     open question this plan has to resolve -- it is the reason N2 (next
     section) runs BOTH coupling modes side by side rather than assuming
     the coupling fix is necessary. Candidate non-coupling explanations
     for Phase 1's failure that N2 should help separate from "needs mean
     drive": raw (non-log) parameterisation, integer delays, single-pulse/
     single-site stimulus, and a single point estimate with no restarts --
     all FOUR of which the single-node study independently showed matter,
     and all four of which N0.3's harness fixes regardless of coupling
     mode.


5. PART N2: BACKPROP + ENSEMBLE + LAPLACE PILOT, 10 NODES, TIER S1
---------------------------------------------------------------------------

Aim
  Test whether the combinations N1 says survive in principle actually
  recover in practice, the way single-node E9-E12 and the Laplace
  calibration tested CRB against real optimisation.

Design
  Same 10-node network, same sites/protocol as N1, coupling fix on. For each
  of several (8-15, compute allowing) independently-drawn random teachers
  (not just the nominal network): fit with the N0.3 harness (>=20 restarts,
  lowest loss selected, nominal-centered starts), then compute a Laplace
  posterior and check 90% interval coverage, exactly as
  scripts/laplace_calibration.py did for the single node.

Pass criteria (fix before running, do not adjust after seeing results)
  * Point estimate: median |error| < 20% for k, a, and c3*c4, across
    teachers.
  * Calibration: 90% credible interval holds the truth 80-98% of the time
    (same band used for the single-node Laplace check).
  * mu: at minimum, moves in the right direction and away from its random
    start (progress > 0 in the single-node study's sense) -- a much weaker
    bar than full identifiability, since this is the first time mu has ever
    had a gradient to work with.
  * No sustained, uncontrolled oscillation introduced by the new coupling in
    any of the fitted networks (reuse the plateau-vs-decay check from
    ei_balance_bifurcation_map.pdf, not a single simulation window).

Interpreting results
  Passes                 -> proceed to Part N3 (scale up).
  Fails only on mu        -> fractional delays were necessary but not
                             sufficient (e.g. too few sites probe conduction
                             time); report as a specific, narrower finding,
                             do not block the rest of tier S1.
  Fails broadly           -> diagnose like the single-node study did:
                             Fisher-good-but-backprop-bad means a landscape
                             problem (try more restarts, or the continuation
                             trick); Fisher-bad-too means a genuine new
                             network-level degeneracy, which is itself the
                             finding (what question C1-C10 in the original
                             single_node_study_plan.txt, or a dedicated
                             network Part C, should target next).

PILOT RESULT (measured this session, ONE teacher, ONE nominal-centered start,
300 iterations, full 8-site x 3-amplitude design used for training -- a
pilot, not yet the >=8-teacher gate above):

  Laplacian (rest coupling, Phase 1's own, unchanged): loss drops cleanly
  0.11 -> 5.5e-6. Recovery: a +0.1%, b -0.2%, g +0.6%, c3 +2.2%, c4 -3.7%,
  mu -0.2%, k -0.0%. c1*c2 = -16.5%, c3*c4 = -1.6% (both under the 20%
  single-node target). Train rel. RMSE 0.0036 (from a start of 0.383).

  Non_diffusive, g=100 (N1's own CRB "sweet spot"): loss PLATEAUS at
  ~7.5e-3 by iteration 60 and never moves again (train rel. RMSE only
  0.128, ~35x worse than Laplacian's). Recovery: g +114%, c1 +141%,
  c2 +168%, c3 -44.6%, c4 +84.4%, mu -33%. c1*c2 = +547% (catastrophic);
  c3*c4 happens to land near truth (+2.1%), likely by drifting along the
  known c3/c4 degenerate direction rather than actually being constrained.

  This resolves N1's flagged open question in the OPPOSITE direction from
  what motivated adding the coupling fix: the Laplacian coupling recovers
  essentially everything from a single start, no ensemble needed, once the
  other N0.3 harness fixes are in place (log-scaled parameters, fractional
  delays, rich multi-site/multi-amplitude design). This strongly suggests
  Phase 1's real failure was never about missing mean drive -- it was the
  four OTHER things the single-node study already found matter (raw
  parameterisation, integer delays, single-pulse/single-site stimulus, no
  restarts), all already fixed here, none touching the coupling term.
  Non_diffusive coupling, even at its CRB-favoured g, gets stuck in a bad
  basin from one start -- a Fisher-good-but-landscape-bad failure, same
  pattern as single-node c1*c2 at a bad operating point. The missing N0.3
  ensemble/restart wrapper is the natural next check on non_diffusive
  before concluding it is unusable, not proof that it is.

  REVISED PRIORITY: run the real N2 gate (>=8 teachers) with the Laplacian
  coupling FIRST (cheap: already works from one start, no new wrapper
  needed) rather than building the ensemble wrapper and re-testing
  non_diffusive first, as section 2's inventory originally ordered it.
  non_diffusive coupling is now a secondary, lower-priority track: revisit
  only if Laplacian's >=8-teacher result exposes a problem a non-zero mean
  drive would plausibly fix (e.g. a parameter that is fine for this one
  teacher but fails across the broader teacher population), or once the
  ensemble wrapper exists for unrelated reasons (single-node still needs it
  too).

8-TEACHER N2 GATE RESULT (measured this session, Laplacian coupling, 8
independently-drawn teachers seed=0..7, single nominal-centered start each,
300 iterations, training = 4 of 8 sites x ONE amplitude (1000), held out =
those same 4 sites at 500/2000 PLUS the other 4 sites at all 3 amplitudes):

  Median |rel_error| across 8 teachers:
    a 0.8%   b 5.0%   g 33.3%   c1 22.7%   c2 27.8%   c3 7.4%   c4 13.7%
    mu 4.6%   k 1.2%
    c1*c2 = 60.0%   c3*c4 = 7.6%
  mu progress: all 8 positive (0.69 to 5.09, median 1.02) -- moves toward
  truth from every start.
  Train rel. RMSE: median 0.180 (start 0.58).  Held-out rel. RMSE: median
  0.184 (start 0.58) -- held-out tracks train closely, so this is NOT an
  overfitting/generalisation gap; it is a training-convergence problem.

  By the letter of the pre-registered pass criteria (median |error| <20%
  for k, a, c3*c4; mu shows positive progress): PASSES. But this is a
  misleading way to read the result, and is flagged here rather than taken
  at face value (standing adversarial-self-review rule): only 2 of 8
  teachers (seed 0, seed 5) actually converged to a good EEG fit at all
  (final loss 1.2e-6 and 2.0e-3); the other 6 plateaued at loss 0.01-0.17,
  ~10,000x to ~100,000x worse, with g off by 23-111% and c1*c2 off by
  55-470%. The three criteria that technically pass (a, k, c3*c4) are
  exactly the parameters that are easiest/stiffest everywhere in this
  model (see single_node_study_plan.txt) -- they survive even a bad fit;
  g and c1*c2, the parameters this plan most needed to test, do not.

  **VERDICT: FAIL in substance** (6/8 teachers did not converge), despite
  a technical pass on the three named headline numbers.

  Root cause, diagnosed rather than left as "sloppy": this held-out split
  cut training richness from the successful single-teacher pilot's 8
  sites x 3 amplitudes (24 conditions) down to 4 sites x 1 amplitude (4
  conditions) -- a much bigger richness cut than intended, made to create
  a held-out set. This reproduces, almost exactly, the single-node study's
  own earlier finding (reports/single_node_conclusions.pdf section 5):
  with a poor (low-diversity) stimulus, final loss does NOT predict
  parameter accuracy and the optimizer gets stuck in bad basins; a RICH
  (multi-amplitude) design was what fixed it there. Teacher 0 (this run)
  and teacher-seed-0 (the earlier full-design pilot) are the SAME teacher
  -- it converged perfectly both times, including here with only 4
  conditions, meaning there IS at least one basin cheap enough to find
  even at this reduced richness; most teachers do not find it from a
  single nominal-centered start.
  No oscillation check was run this pass (not yet verified either way).

  Decision: do not re-run the ensemble wrapper yet (that fixes "stuck
  basin", not "too little information"). Instead redo the held-out split
  to restore multi-amplitude richness within the training set: train on 4
  of 8 sites x ALL 3 amplitudes (12 conditions, matches the richness that
  worked for the single pilot teacher, just on half the sites), hold out
  the other 4 sites completely (a genuine site-generalisation test, not
  conflated with amplitude-richness-starvation). This isolates "does a
  network trained on half the anatomy generalise to the rest" from "is 4
  sites x 1 amplitude enough signal to fit at all" (it is not, for 6/8
  teachers) -- the two were accidentally conflated in this first attempt.

  Median |rel_error|: a 0.6%  b 5.0%  g 30.3%  c1 32.3%  c2 35.1%  c3 5.7%

  Train rel. RMSE median 0.195 (vs first attempt's 0.180); held-out median
  0.145 (vs 0.184) -- marginally better held-out, marginally worse train,
  i.e. essentially NO CHANGE in the aggregate picture despite 3x the
  training data. a, k, c3*c4 still technically clear the 20% bar; g and
  c1*c2 still do not (median ~30% and ~57%, both runs).

  Per-teacher final loss, run1 -> run2: t0 1.2e-6->3.4e-6 (both excellent),
  t1 0.17->0.071 (improved but still bad), t2 0.028->0.004 (now good),
  t3 0.12->0.056 (improved but still bad), t4 0.030->0.016 (still

  t7 0.011->0.0069 (decent both). Net: tripling training richness helped
  4/8 teachers, hurt 1/8, left the overall pass/fail picture unchanged --
  richness was not the dominant factor after all.

  **The dominant factor, found by checking what the consistently-bad
  teachers (t1, t3, t6) have in common across BOTH designs:** their drawn
  stimulus gain k is 45-50% BELOW nominal (log-offset -0.66, -0.57, -0.56)
  -- the three largest negative k offsets of all 8 teachers, by a wide
  margin (next closest is t4 at -0.10). Spearman correlation of k's
  log-offset against log10(final training loss): rho=-0.79 (p=0.02, run
  1), rho=-0.95 (p=0.0003, run 2) -- strong and gets STRONGER with more
  training data, meaning this is a real effect, not an artifact of too
  little data. The SIGN matters, not the magnitude (|k offset| alone does
  not correlate as strongly): teachers with a WEAKER-than-nominal stimulus
  gain are the ones that fail, not teachers whose k happens to be far from
  nominal in general.

  **Mechanism (consistent with, not a new finding beyond, the single-node
  study's own earlier diagnosis):** the same fixed stimulus amplitudes
  (500/1000/2000) produce a weaker EFFECTIVE drive for a teacher whose own
  k is low, likely leaving that teacher's network less engaged for the
  same nominal protocol -- structurally the same problem
  reports/DECISIONS.md's 2026-11-22 "Mechanism behind the c1.c2/c3.c4
  recovery failure" entry already diagnosed for the single node ("a single
  fixed p does not put every teacher in the same dynamical regime"), now
  reappearing at network scale through a different nuisance parameter (k,
  not the tonic drive p, since the network pilot's stimulus is pulsed, not
  tonic) but the same structural cause: ONE fixed protocol cannot put
  every teacher in the same effective regime when teachers differ in how
  strongly they respond to it.

  Decision: before reaching for the ensemble/restart wrapper again (a
  genuinely different diagnosis -- "stuck in one of many basins" vs "wrong
  regime entirely"), the next experiment should calibrate stimulus
  amplitude PER TEACHER (e.g. scale amps by nominal_k / teacher_k, or
  screen each teacher for an engaged-but-stable operating amplitude before
  fitting, mirroring the single-node per-teacher-p calibration already
  recommended once in this study) rather than assume a fixed amplitude
  protocol works for every random draw. Not yet run this session --
  reported here as the diagnosed next step, not yet executed.

6. PART N2.5: DIAGNOSE g's SYSTEMATIC BIAS (decided 2026-11-26, before N3)
---------------------------------------------------------------------------

Aim
  N2 passed its three named criteria, but g (median |error| 27.1%, biased
  low in 6/8 teachers) was flagged, not resolved. Before spending compute on
  N3 (scale up) or building the missing network-scale Laplace calibration,
  find out WHY g fails -- this plan's own N1/N2 structure already showed
  (teacher 3, teacher 6) that "CRB-good-but-backprop-bad" is the single most
  recurring failure mode in this whole study, and g looks like another
  instance of it, not a new kind of problem. See reports/DECISIONS.md
  2026-11-26 ("Holistic review after the N2 pass") for the full reasoning.

Findings that motivate this (from already-saved data, no new compute)
  1. g is NOT a sloppy/degenerate direction locally: the nominal-teacher
     Fisher table (results/identifiability/nominal.json, "8 sites, 3
     amplitudes") gives g a CRB of 0.0033% -- the best-identified parameter
     in the table -- with only modest correlations to other parameters
     (|corr| <= 0.54) and near-zero loading on either of the two softest
     eigendirections (those are dominated by c1/c2/c3/c4, as single-node
     work already found). This rules out "not enough information" as the
     cause.
  2. The 8 already-saved N2-gate ensemble fits (results/recovery_ensemble/
     *_N2full_ens_t*.json) show a clear directional pattern, not scatter:
     the 3 teachers with the LOWEST true g (523, 586, 750) all converge
     close to truth; the 4 with the HIGHEST true g (1172-1461) all converge
     to a much narrower, much LOWER band (482-813) regardless of which
     direction their restart started from (e.g. t4 started at 1219, already
     close to its truth of 1461, and was pulled DOWN to 505). This looks
     like an attractor around g~500-800 pulling high-g fits down, not noise.
  3. Mechanism hypothesis, grounded in a bug this plan already found once
     (N0.3): core/diffsim.py's step_ms computes
     rE = noise + g*coupling + c2*E_s, then clips with
     rE_bd = U_BOUND*tanh(rE/U_BOUND), U_BOUND=500 -- the exact clip that
     silently killed non_diffusive coupling's gradients at the teacher's
     nominal g=1000 (N0.3). Laplacian coupling is zero-mean at rest so this
     was not suspected there, but during a stimulation pulse (the only time
     g's gradient is exercised) g*coupling for a HIGH true g could
     intermittently push rE past the clip for some node/timestep, locally
     killing d(rE_bd)/dg in exactly the direction that would produce "fits
     prefer a lower g than the truth whenever the truth is high." Not yet
     checked directly.

Task: DONE (2026-11-26, via new syn_brain/scripts/diagnose_g_clip.py -- an
instrumented reimplementation of diffsim.py's step_ms, verified byte-for-
byte equivalent to the real ds.run() before trusting its numbers, since a
first pass gave implausible values that turned out to be a genuine (very
large, very brief) transient, not a bug -- see verification note below).

RESULT: CLIP CONFIRMED, with much more precise evidence than a yes/no
check. Replayed each teacher's own TRUE parameters through the exact
training protocol (4 of 8 sites x 3 amplitudes), computed the clip's local
gradient-survival factor (sech^2(rE/U_BOUND), i.e. how much of d(loss)/dg
actually gets through the tanh clip -- 1.0 = undamped, 0.0 = dead),
averaged over the settled post-transient window (t=150-400ms):

  teacher  true_g   mean grad-survival   g rel.error (N2 gate)
  t0        523.0         0.835              +0.0%
  t1        585.8         0.686              -5.1%
  t6        750.0         0.604              -20.8%
  t5        880.7         0.551              +20.6%
  t2       1223.1         0.385              -33.5%
  t3       1205.8         0.377              -48.4%
  t7       1172.4         0.427              -58.9%
  t4       1461.4         0.424              -65.4%

  Spearman true_g vs. grad-survival: rho=-0.90 (p=0.002) -- higher true g
  mechanically produces more clip attenuation, exactly as the hypothesis
  predicted (g directly scales the term being clipped).
  Spearman grad-survival vs. |g rel.error|: rho=-0.79 (p=0.02) -- less
  surviving gradient predicts worse recovery.
  Spearman true_g vs. |g rel.error|: rho=0.88 (p=0.004) -- and so, as the
  direct, observable consequence, higher true g predicts worse recovery.

  There is also a large, brief TRANSIENT the first analysis almost
  mistook for a bug: g*coupling spikes to 5-600x U_BOUND for ~10-20ms
  immediately after the pulse (e.g. teacher 0 -- the BEST-recovering
  teacher -- hits |g*coupling|=147,649 at the pulse's end), then decays
  over ~150ms into the settled regime the table above measures. This
  transient occurs for every teacher regardless of true g (confirmed by
  direct comparison against real ds.run()'s output EEG, which stays sane
  throughout -- the clip is doing its job of keeping the forward
  simulation bounded even during this spike; it is the GRADIENT through
  that bounded output that dies). The settled-window numbers above, not
  the transient, are what distinguish teachers from each other.

  **Verification note (so this isn't trusted on a first implausible
  number):** the reimplementation was checked against real ds.run()'s
  actual output EEG for teacher 0 (max|EEG|=29.9, no NaN, fully sane)
  before trusting the instrumented numbers -- the apparent "bug" (rE in
  the hundreds of thousands) turned out to be this real, large, brief
  transient, not an implementation error. Recorded here because the
  instinct to assume a bug was initially correct methodology, and the
  resolution (verify against known-good output) is the generalisable
  lesson, not just a one-off note.

Decision: fix is needed, but WHICH fix is a genuine design choice, not an
obvious bugfix -- raising U_BOUND uniformly could reduce gradient death
for high-g teachers' settled dynamics (good) but also reduces the margin
that specifically prevented an earlier, more severe failure mode in this
same investigation (non_diffusive coupling's catastrophic blow-up at
nominal g=1000, N0.3) during early, far-from-truth fitting iterations
when parameters can be in much more extreme configurations than any
teacher's own true value -- a global change here could trade "g is biased
low" for "training occasionally diverges," which is not obviously a
better trade without testing it. Flagging this as a stop-and-ask point
(CLAUDE.md: "a required design choice is not specified and different
choices could change the conclusion") rather than picking a value and
re-running the multi-hour N2 gate on a guess.

RAISING U_BOUND: TESTED AND DISCONFIRMED (2026-11-26, William chose this
option to try first). Stability check across U_BOUND in {2000, 5000,
10000} on all 8 teachers + the nominal start: no NaN/Inf anywhere, EEG
stays sane -- numerically safe. But the gradient-survival check that
matters shows this does NOT fix the problem: t0/t1/t5/t6 (already the
better-recovering teachers) improve substantially (e.g. t1: 0.686->0.954
at U_BOUND=10000), while t2/t3/t4/t7 (the worst four) barely move at all
(0.37-0.44 across the whole range tested). Pushing U_BOUND three more
orders of magnitude (5e2 to 5e5) on just those four teachers settles the
question: the ratio of settled-window coupling magnitude to U_BOUND
converges to a CONSTANT ~3-4x and stops shrinking (t2: 38.6x at U=500 ->
4.6x at U=5000 -> 3.3x at U=50000 -> 3.2x at U=500000; same pattern for
t3/t4/t7). **This means these four teachers' network dynamics have no
bounded, non-saturating equilibrium for any clip value -- raising U_BOUND
cannot work by construction, not just insufficiently, because the system
settles into a proportionally larger steady state at whatever bound is
set.** U_BOUND is not an optional safety margin for these parameter draws;
it is the only thing preventing outright divergence. Disconfirmed by
direct test, not argued from the mechanism alone.

Remaining options, now that this one is ruled out: (a) investigate the
underlying instability itself -- why this specific coupling formulation
has no bounded equilibrium above some g threshold, whether it is specific
to this anatomy/connectivity or general to Laplacian coupling at this
parameter scale -- a genuinely open research question, not a quick
diagnostic; or (b) accept and scope this as a documented limitation: this
method reliably recovers g only in roughly the range t0/t1/t6 occupy
(~500-750), and future teacher draws / N3 work should either restrict g
to that range or explicitly carry this caveat forward rather than
treating the whole g axis as in-scope.

NON-DIFFUSIVE COUPLING AS AN ALTERNATIVE: TESTED, DOES NOT HELP -- MAKES
IT WORSE (2026-11-26). Motivation: Laplacian coupling sends raw, unbounded
membrane-potential-like values (E) between nodes; non_diffusive coupling
sends a sigmoid-bounded firing rate (S(E), capped at vmax=5) instead --
structurally immune to the "no bounded equilibrium" problem above, and
arguably more physiologically plausible (real inter-areal connections are
carried by rate-limited spikes, not raw potentials). Confirmed this
directly: a g-sweep across U_BOUND values under non_diffusive coupling
shows clean decay and stable, bounded EEG (no NaN/Inf) across g=50-300,
with no sign of the scale-invariant runaway Laplacian showed.

Ran the full ensemble gate (5 restarts/teacher, same 8 teachers, same
held-out design, non_diffusive coupling, g=100 -- N1's earlier CRB "sweet
spot" for this mode) to test whether removing the structural instability
actually improves backprop recovery. **It does not -- g recovery is WORSE,
and mu, previously Laplacian's cleanest win, is badly broken:**

  Median |rel_error|, matched non_diffusive (teacher=student, g=100) vs
  matched Laplacian (the N2 gate above):
    param   non_diffusive   Laplacian
    a            1.8%          0.3%
    b           16.8%          1.5%
    g           58.4%         27.1%
    c1          43.8%         34.3%
    c2          56.2%         26.6%
    c3          32.8%          1.5%
    c4          38.7%          5.8%
    mu          59.5%          0.4%
    k            0.2%          0.3%
    c1*c2       75.2%         12.0%
    c3*c4        9.0%          4.2%

  g's median error is roughly DOUBLE Laplacian's, with a catastrophic
  outlier (teacher 3: +1351%). mu -- which had essentially perfect,
  unanimous positive progress under Laplacian (median +1.01, all 8
  positive) -- now has NEGATIVE progress (moved AWAY from truth, worse
  than its random start) for 4 of 8 teachers, median |error| 59.5%. c1*c2
  degrades from a passing 12.0% to a failing 75.2%. Only a, k (already
  the easiest parameters everywhere in this whole study) and c3*c4
  (roughly comparable, 9.0% vs 4.2%) are unaffected.

  Train/held-out RMSE median 0.081/0.083 (vs Laplacian's 0.078/0.068) --
  comparable overall fit quality, meaning this is NOT a case of the
  non_diffusive student simply failing to fit the data; it fits about as
  well as Laplacian does, while landing on substantially WRONG parameter
  values to do so -- a sloppier, more degenerate loss landscape, not a
  harder-to-reach one.

  **Likely mechanism (not yet directly verified, flagged as the honest
  open question rather than asserted): non_diffusive coupling has no
  analogue of Laplacian's self-cancelling `dg @ E` term** (coupling = -1 x
  (D-W) x E at rest for Laplacian, always pulling a perturbed node back
  toward its neighbours' average; non_diffusive's coupling is purely
  additive/positive, no restoring term of its own). This removes a
  structural source of information that let Laplacian's g and mu load
  distinctly on the EEG; without it, g's network-wide drive and mu's
  conduction-delay shaping of that same drive become more mutually
  entangled, which would explain BOTH symptoms at once (g degrading
  further AND mu newly breaking) as two faces of the same new
  degeneracy, rather than two unrelated problems.

  **Revised verdict: the physiologically-motivated coupling choice is not
  automatically the more IDENTIFIABLE one.** Laplacian coupling, despite
  having a genuine, structural high-g instability that non_diffusive
  avoids, has a far more tractable optimization landscape for every
  parameter except g itself. Trading a clean, well-understood, localized
  failure (g only, only above ~750-1000, now precisely characterized) for
  a diffuse one (g worse, mu newly broken, c1*c2 much worse) is a bad
  trade on the evidence so far. **Decision: do not adopt non_diffusive
  coupling as a replacement for Laplacian.** Keep both coupling modes
  available in the codebase (already parameterised via
  `coupling_mode=`), but treat Laplacian as the default and non_diffusive
  as a secondary, special-purpose option, not a fix for g.

MISMATCHED-COUPLING ROBUSTNESS TEST, RESULT (2026-11-27): neurofe's real
Laplacian-assumption framework does NOT stay robust if reality is closer
to non_diffusive coupling -- this is the worst of all three conditions,
by a wide margin, and the degradation shows up even in raw fit quality,
not just parameter recovery.

  Same 8 teachers, same held-out design, 5-restart ensemble. Teacher
  generated under non_diffusive coupling (g=100); student fit assuming
  Laplacian coupling (added `--student-coupling-mode` to recover_clean.py
  for this). g is excluded from the recovery judgment here (no shared
  ground truth across coupling modes -- see N0.1's docstring); only
  a, b, c1-c4, mu, k (node-intrinsic, coupling-independent) are judged.

  Median |rel_error|, three-way comparison:
    param   matched Laplacian   matched non_diffusive   MISMATCHED
    a             0.3%                 1.8%                4.5%
    b             1.5%                16.8%               16.2%
    c1           34.3%                43.8%               83.4%
    c2           26.6%                56.2%               86.3%
    c3            1.5%                32.8%               16.8%
    c4            5.8%                38.7%               46.9%
    mu            0.4%                59.5%               37.5%
    k             0.3%                 0.2%                2.4%
    c1*c2        12.0%                75.2%               98.1%
    c3*c4         4.2%                 9.0%               54.4%
    train RMSE   0.078                0.081                0.170
    heldout RMSE 0.068                0.083                0.180

  **The mismatched condition is unambiguously the worst on every measure
  that matters for E/I-balance interpretation.** c1*c2 is essentially
  destroyed (98.1% median error, with one teacher at +3146%); c3*c4
  degrades to 54.4% (worse than either matched condition, which were 4.2%
  and 9.0%). Train AND held-out RMSE are both roughly DOUBLE either
  matched condition's (0.170/0.180 vs ~0.08 for both) -- meaning a
  Laplacian student genuinely CANNOT reproduce non_diffusive-generated
  data as well as a matched student can, at ANY parameter setting; this
  is not just a parameter-recovery problem, the two coupling mechanisms
  produce qualitatively different dynamics that a mismatched model family
  cannot fully mimic. mu is bad (37.5%) but, notably, less bad than the
  matched non_diffusive case's 59.5% -- and its progress is genuinely
  mixed (4 of 8 positive, 4 negative), not uniformly destroyed like
  c1*c2/c2.

  The student's fitted "effective Laplacian g" clusters low (9-40) for
  7/8 teachers, one outlier at 204 -- far below any matched-Laplacian
  teacher's true g (500-1500). Reported for interpretation only: a
  Laplacian student fitting non_diffusive-generated data apparently
  compensates by using very weak inter-node coupling and absorbing the
  mismatch into (badly wrong) local loop-gain parameters instead --
  consistent with c1*c2/c2 being where the damage concentrates.

  **This is the single most practically important finding of the N2.5
  investigation.** If real cortical coupling is closer to the bounded,
  rate-based mechanism non_diffusive coupling represents (the more
  physiologically grounded assumption -- see the conversation's earlier
  discussion of TMS afterdischarges and real synaptic rate-limiting),
  then applying neurofe's actual Laplacian-only framework to real TMS-EEG
  data would not just fail to recover network-coupling-strength (already
  known) -- it would produce SUBSTANTIALLY WRONG loop-gain (E/I-balance)
  estimates, the exact quantities this whole study's single-node and
  network phases both treat as the primary scientific target. This is a
  limitation of neurofe's modeling assumption itself, not of this
  identifiability study's method.

  Decision: do not treat this as a reason to switch coupling modes (both
  matched-non_diffusive and mismatched are worse than matched-Laplacian
  on every measure) -- treat it as a documented, now quantified caveat
  that belongs alongside every future result this framework produces:
  loop-gain (c1*c2, c3*c4) recovery is reliable ONLY to the extent
  Laplacian coupling is itself a reasonable approximation of the true
  coupling mechanism, and this has not been validated against real brain
  connectivity data. Flagging as a finding for executive_summary.pdf and
  README.md, not a blocker for proceeding with Laplacian-based N3 work
  (which this evidence continues to support as the best available
  choice), but a limitation that must travel with any claim this study
  or neurofe's real pipeline makes about recovered loop gains.

9. RISKS
------------

  The non-diffusive coupling engages the loop but also makes the network
  bistable or oscillatory at the scale of the whole network, not just one
  node
      -> N0.2's tiny-scale sanity check first, using the two-window /
         equilibria-style stability check (not a single simulation window),
         is specifically there to catch this before 10+ nodes.
  Fractional delays fix mu's gradient but mu is still practically
  unidentifiable (e.g. too few sites span a useful range of conduction
  times)
      -> N1 measures this analytically before any training; if the Fisher
         bound on mu is poor even with the gradient fixed, that is itself
         the (negative) finding, not a bug to chase.
  Network-scale compute is much larger than single-node (more parameters,
  more conditions, more restarts x teachers)
      -> N1 (Fisher only) is deliberately cheap and gates N2 (training);
         N2 itself stays at 10 nodes / tier S1 / 8-15 teachers, the smallest
         design that can still produce a believable calibration check,
         before any tier or node-count increase.
  diffsim.py's fixes were built for a different purpose and may have
  untested edge cases at network scale (e.g. fractional-delay interpolation
  at very short delays, or interactions between log-scaled parameters and
  the new coupling term)
      -> N0.3's unit test (reproduce the single-node E9 result) is there
         specifically to catch harness bugs before they are mistaken for
         network-level findings.
